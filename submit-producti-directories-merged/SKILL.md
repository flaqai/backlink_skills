# 外链自动提交合并版

## 目标与用法

在用户给定的站点范围内，完成免费目录、公司/账号资料、项目展示、免费广告或新闻稿等非内容编辑器入口的品牌网址投递，以及获授权的一对一官方联络邮件。简单站连续处理，复杂站预填后留给人工，逐站如实记录。

有指定站点顺序就照做；未指定时可按现场安排。搜索、等待和取证按实际需要，不要求逐项 PASS/FAIL、固定轮次或通读附件。已核实资料可复用，授权以本批范围为准。

## 开始与范围

- 开批前按[启动模板](references/workflow.md#批次启动模板)确认各项。先用本批对话和已确认资料预填；缺多项就主动发可复制的模板，只留缺项待补；只缺一项直接问；齐全且获授权即按范围执行，不再确认。用户明确索要模板时直接给。自动化和发信授权不沿用上一批；读资料、分析和修改技能无需投递许可。
- 「只允许预填」时填好并保留原页，由用户提交；模型只在交回后按授权核验，不代点最终提交。允许填表并提交也不包含发信；官方联络邮件另按本批明确授权处理。
- 默认允许普通注册、登录及无费用营销订阅，用户可收紧范围。需要登录时优先复用已授权会话，再用 Google OAuth（谷歌账号直接登录）或个人 Gmail；企业邮箱只在确有必要时使用。
- 免费排期默认选本批允许范围内最早可用的档期，记录日期，不逐站确认。用户如有限定，批次开始时记一次；没有合适的免费名额就记录原因，不改选付费。公开点赞、评论等互动及官网改动默认不做；可选则跳过，必需且未获授权则记原因并继续其它站。
- 已授权批次中，普通服务条款和隐私政策同意框作为填表步骤处理：工具允许时直接勾选，已勾选则保留，确认状态后继续。不读全文、不另审查、不再请示；工具要求审批或拒绝代勾时按[人工接力](references/workflow.md#人工接力)处理。
- 官方联络邮件需当前批次明确授权发送，并核验指定渠道和发件身份（如 Gmail 或飞书公共邮箱）。核对官方收件人、内容及去重后直接发送，不逐封请示；工具要求原生审批时按其处理。付款、自动续费、强制互链、官网或账号归属变更不在普通投递范围内。遵守站点明确的自动化限制，不绕过验证码。
- 只用核实的产品和公司资料；有核实资料的适用描述、图片与资料字段填全，未知字段不编造。可选互链留空，必填资料缺失则说明原因。公开链接文字用品牌、产品名或规范网址。
- 短贴 Note、长文 Post/Article 及无法可靠分类的内容编辑器均不操作：不填文案、不存草稿、不交人工发布。其它公开展示网址的入口按真实用途和免费权益判断；低质量、小众或旧目录不单凭质量排除。

## 每站怎么做

只在本批明确允许的子页中选符合目录要求的一页，名称、描述和分类与该页匹配。已确认「只投官网」或允许的子页都不适合时，用本批确认的官网网址（`Canonical URL`）；官网也不适合就跳过。选子页时用 `Target URL` 记录实际网址，选择或回退原因简记在结果中。去重查询包含目标网址和对应工具名称；换路径不构成新产品或重投权限。

1. **找当前入口。** 从首页导航、页脚、真实链接或账户区确认入口，旧深链作线索。优先合适的商家、资料、目录或项目展示路径；找到可用路径就推进，不为凑齐类型扫遍全站。遇付费/合作页再找普通免费路径。只有常规手段找不到入口时，才用视觉检查页面首、中、尾，核验所见链接。读套餐、按钮或回执时可直接用视觉，不受找入口的兜底条件限制。
2. **防重复。** 先查历史记录；恢复同一条记录时保留已知状态，只更新新证据。已有提交（含用户明确报告）、待审、公开条目或结果不明时，不自动重做。站内用固定查询集：品牌名、规范网址（含尾斜杠变体）、裸域名、实际发现的标题词序变体；确认搜索确实触发且结果已更新。相关候选必须核验实际出站网址，标题只作线索。新队列项命中已有条目才记重复。后台、近期和分类列表按需补查，查不全就记“去重未能确认”，不无限翻页；仅本批明确允许去重例外且允许提交时，才直接尝试一次。
3. **填写并提交。** 尽早检查页面可见的免费名额、必做动作、必填项、字数、分类和图片规格；后续才显示的，在相应步骤检查，不猜缺失限制。提交前回读关键值，确认图片上传或预览成功；方案切换或刷新后只重查受影响项。遇未授权的必做动作，停该站相关操作并继续其它站。验证码等人工验证出现时，填好可填字段、上传素材，保留原页并交代剩余动作；短时效验证码与提交必须连续时由用户一并完成。
4. **按证据收尾。** 与本次产品和动作匹配的原生回执或后台状态可证明收件或待审；普通跳转、点击、清空表单、草稿不够。回执模糊时按需补查，公开收录须核验公开页。只有用户明确报告已提交、且没有匹配的站点回执时，才单列 `submitted — user reported`；仅要求不核验时按已知事实记录，不推断成功或重投。

## 失败和重试

默认使用 CDP（浏览器调试协议直连），用户另有指定就照做。CDP 技术失败先读当前页面和目标，判断原因再调整；同一失败脚本不盲重跑，修正后仍失败可转人工或换已获准的方式。明确拒绝、验证、重复、付费或强制互链是该动作的阻断，不能靠换工具绕过。

Google OAuth 若遇网站或网络不稳导致的白屏、超时等临时加载失败，不直接跳过。在原浏览器和账号下刷新受影响的登录页，最多 3 次，每次等页面响应再判断；恢复即继续，仍无法加载则保留原页交人工。出现明确拒绝、账号安全提示或需人工验证时停止刷新；刷新仅用于恢复登录页，不重放最终提交。

已授权提交的表单默认只点一次。只有用户明确授权该站重试和次数时，才按上限执行；重试前先判断上次是否可能已成功，成功或遇明确阻断即停。结果不明不会自行产生重投权限。表单提交、登录链接请求和联络邮件分别计数。官方联络邮件只发一次，结果不明时按需只读核验，保留可用页面，不重发。

保持用户指定的浏览器、账号和原页；不改指纹浏览器管理端/配置，可按既有授权恢复崩溃的 profile。清理本任务无关的残留页时保留人工验证、结果不明和用户需要的标签。

## 记录与交付

每站记当前入口、去重结论、实际动作次数、原生回执或阻塞、证据及下一步。只添加实际适用字段；新记录用 [精简模板](assets/submission-record-template.md)，状态和条件字段需要时查 [记录说明](references/status-model.md)。技术异常或瞬时回执需要时查 [执行参考](references/workflow.md)，正常站无需加载。

执行期间及时保存结果，继续其它站；除缺关键授权、信息或用户主动询问外，批末统一逐站交付。汇报前以最新逐站记录核对待办，已发信、已提交、已入队或已排期的事项移出待决清单；排期或入队不算已发布。同一个待确认问题合并一次，列出受影响站点。恢复时先查记录、当前页和授权，不重新确认已明确的信息或重放已完成动作。必要进度沟通遵循运行环境要求。

`already_listed` → `duplicate — no action`；`captcha_wait` → `blocked — manual verification`。汇报前按[记录说明](references/status-model.md)使用现有状态和字段，排期日期及细节写在结果说明；运行 `scripts/audit_submission_record.py`，能据实修正的先修，剩余错误如实报告。审计通过不证明公开收录；旧记录继续按旧格式校验，不补造证据。

公开技能本身只用占位符，不含实际任务品牌或资料。可分享投递记录使用别名和受控证据，移除凭据、原始联系方式、会话及带令牌链接。这个公开包的审计器只接受 `shareable` 记录。
