# 博客写作编辑核心参考

先阅读[术语约定](../../docs/terminology.zh-CN.md)。本技能只提供编辑判断框架，不是可执行角色。实际调研、成稿、修复和文件产出由 `blog-3p-writer` 完成；默认 WQ 的同上下文对抗式自查仍由同一 W 完成。只有 WR 风险升级或用户要求时，才由 `blog-3p-review` 作独立审稿；WQ 凭据不得冒充其批准。

## 编辑原则

- 先完整回答冻结的读者任务，再以透明、相关且有证据边界的方式保留用户确认的次要 CTA。去掉 CTA 后，文章仍必须独立有用；不得把产品主张写成未经证明的可靠性、排名、实测或可用性结论。
- 每个实质性事实都应能回溯至来源台账，或明确标为分析/观点与不确定性。不要用流畅表达代替证据。
- 默认让 W 用一个 `research/evidence-pack.json` 连续承载本篇关键词、本地化、来源、事实边界和图片计划；可生成查阅视图，不双写研究文档。项目内稳定证据只在精确匹配时引用并记录本篇差异，无命中不造空缓存。WQ 由同一 W 锁定候选、反方自查、定向修复并绑定最终哈希为 `AUTHOR_QA_READY`；高风险或用户要求的 WR 才由独立 R 完整审查引用记录和成稿。可选成文前研究挑战也只存在于 WR。
- G 冻结的 `topic_slot` 约束读者任务、核心意图、市场、差异化角度和禁止偏离项；它不冻结字面关键词或标题。W 可在该边界内改善当地自然变体与标题；若证据要求换读者问题、市场或承诺，停止并交回 G 的既有例外决策，不能自行改题。
- 标题以读者任务、主题清晰度、独特价值、自然语言和目标市场为准；关键词/长度检查只是提示。默认平台标题等于唯一基准稿标题，禁止把短的关键词占位标题误送到平台字段。
- 多语言表达先采用同语言、同地区、同意图的现有品牌站用语，再查地区 SERP 自然变体，最后才可在两次无共识检索后使用有记录的 `MODEL_TRANSLATION_FALLBACK`。Google Trends 如可用，只比较英文概念和英文长尾候选，且仅作全球相对关注度背景；不能证明本地用语、搜索量、低基数/高势头、本地需求、商业意图或模型能力。数据不足、无 `Breakout` 或无清晰趋势时，不得强求趋势证据；长尾读者问题仍由品牌站与地区 SERP 的有边界证据决定。平台资料仅可影响技术深度、示例形式、语气与交付风险，不能证明关键词、自然变体、搜索意图、当地需求或热门度。
- 配图必须解释相邻内容。适用指南、教程、对比、评测和长解释文时，以 `LEAD`、`MIDDLE`、`CLOSING` 覆盖组织图片；每张图有独立读者作用、Alt、图注、位置和视觉审查，不能用首图或尺寸凑数。
- 当前 `article-package.json@1.5` 固定 `canonical/article.html`、metadata、evidence pack 与 visual manifest 为唯一上游来源；同一编译器从这些声明来源生成 HTML 主交付页和 Markdown 备用投影。适用 WQ/WR 质量角色语义审 HTML 与源数据；Markdown 仅 `COMPANION_DUAL_READ_REQUIRED` 时语义双读。WQ 任何绑定后可见改动须重新作者自查，不能使用独立 R 的 Delta 名义。
- 唯一基准稿的标题层级是写作意图与本地结构审稿对象；平台读者页的最终层级只能由 `HUMAN_ACCEPTED` 后的公开渲染视觉裁定。

具体执行由 `blog-3p-writer`、`blog-3p-review` 和其引用的[编辑标准](references/editorial-standard.md)、[跨语言 SEO 说明](references/cross-language-seo.md)承担。机器字段、状态码、文件路径与 Skill ID 保持不变。
