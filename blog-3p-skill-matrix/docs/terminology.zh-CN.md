# 博客 3P 术语约定

本矩阵以中文解释工作流，但不改动机器需要识别的字段、目录、状态码、角色 ID、命令参数或文件名。首次出现时可同时给出英文代码名；后续一律使用下列中文名称。

| 代码名或旧称 | 统一中文表达 | 说明 |
| --- | --- | --- |
| campaign / 战役 | 内容项目 | 一次由用户确认范围、文章集合与交付状态的博客任务。`campaign.json` 等机器名称不变。 |
| lane / 泳道 | 文章协作组 | 某篇文章的有界任务记录与 `articles/<article_id>/` 路径；默认 WQ 是 W 写审一体，高风险 WR 再派独立 R；每篇独立保留质量凭据与问题项。 |
| worktree | 独立 Git 工作区 | Git 提供的文件与分支隔离能力；当前仅是显式例外，不等于可见子代理或默认文章隔离。 |
| G / gatekeeper | G（需求与交付把关人） | G 冻结用户需求、协调质量路线并验收需求保真；不代替 WQ 自查或 WR 独立 R 判断。 |
| WQ / author QA | 写审一体 | W 在同一上下文作对抗式自查与定向修复，最终 `AUTHOR_QA_READY` 是作者质量凭据，不是独立审稿 `APPROVED`。 |
| WR / independent R | 写作与独立审稿 | W 连续成稿后由独立 R 完整审阅；高风险或用户明确要求时使用。 |
| harness / 机架 | 本地流程工具 | 初始化、状态保存、结构校验与恢复所用的本地工具，不作编辑判断。 |
| owner | 用户或经授权的任务确认人 | 指有权确认范围、平台/账号映射与唯一基准稿变更的人。 |
| handoff | 人工发布交接 | 将已经验收的本地交付文件交给人工在原生平台操作的阶段。 |
| payload / 载荷页 | 可视化富文本交付页 | 浏览器中从上到下显示标题、带图片注释正文和 SEO 信息的人工复制页。 |
| canonical | 唯一基准稿 | 文章的唯一规范内容来源；读者可见修改必须更新其指纹并重新进入相应复审。 |
| artifact / 工件 | 交付文件 | 可审计的文章、报告、清单、图像或交接文件。 |
| finding | 问题项 | 使用稳定 ID 追踪的规则违反；ID 本身不翻译。 |
| delta capsule | 变更摘要 | 列出已批准基线、准确改动和受影响风险面的有限复审说明。 |
| dispatch | 启动或分配文章任务 | 在确认范围与资源就绪后，创建或继续一篇文章的协作组。 |
| steward | 平台样本研究角色 | 项目级、可复用、只读的运行支持角色；不选平台、不写文章、不做质量判定。 |
| adapter | 可选只读工具 | 搜索、公开网页、Trends 或 SEO 工具等证据来源；不可用时记录事实，不得臆造。 |
| fixture | 测试样例 | 用于验证规则或工具行为的中性测试内容，不是实际文章。 |

文章标题、正文、关键词、元数据、图片 Alt 和图注仍必须使用冻结的目标语言。本术语表仅本地化工作流说明、人工交接界面和代理指令，绝不把多语言博客内容强制改成中文。
